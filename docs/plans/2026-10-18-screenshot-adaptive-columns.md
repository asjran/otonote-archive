# 截图识别适配不同列数

## 问题与改动

旧路径按 1280 宽度套用固定坐标：角色六列、留影四列。不同机型的列数、缩放或列表偏移会裁错卡片，继而影响卡面、数字与角标。

正式 Worker 现在从 OpenCV 边缘中寻找重复卡框，推断列位置、卡片尺寸与完整行。每张裁片缩放到现有 ORB/OCR 标准尺寸，再利用同行可见数字的共同基线校准位置。没有足够一致锚点时不读取养成，交给用户补齐；低置信度卡面仍默认不选。不更换索引格式、不新增服务或上传截图。

仅增加列数选项仍无法处理卡片尺寸、边距和滚动变化；增加设备模板仍会遗漏新布局，因此采用图像定位。保留游戏卡框比例、相邻间距、数字样式的限制，要求横屏且至少两列完整卡牌；不是通用物体识别器。独立历史原型工具继续保持其既有实现，本次修改正式网站路径。

## 验证

- 59 项 Node 专项回归通过：2–9 列角色/留影、缩放与偏移、缺格、底部半张卡、空图、数字基线偏移、无锚点拒绝读值、取消重试、库存合并与版本校验、静态 Worker 打包和按需加载。
- 11 项 Python 候选构建与代码包测试通过。新几何回归已加入正式候选的固定门禁。
- 本机 Chrome 运行真实 OpenCV/ORB/Tesseract，三张既有校准图的逐卡结果与旧实现完全一致：56 个完整区域、49 个卡面接受、53 个数字、56 个星级/花瓣，三种截图类型均正确。使用既有旧索引进行同源前后对照，未匹配的卡面不视作新算法错误。
- 将既有卡片素材重排为八组截图：角色特训五列，角色等级三/五/七/八列，留影三/五/六列；同时改变尺寸、起点并加底部半张卡。84 个完整区域全部定位；所有已接受身份与可对照的非空养成值均无差异。部分数值/角标因缩小或置信度不足留空。这是构造回归，不是独立机型准确率。
- 完整 Node 测试执行 1117 项：1089 通过，28 项因干净 worktree 缺少未分发的生成数据失败（计分规则、谱面、演出皮肤、生成目录与养成 manifest 等）。没有宣称全套通过。独立前端构建可完成，不依赖这些内容数据。

浏览器与测试日志留在仓库外的本机临时验收目录；截图、特征索引、媒体、依赖及构建输出不提交。
