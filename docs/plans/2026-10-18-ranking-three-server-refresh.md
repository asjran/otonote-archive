# 三服榜单更新修复与接入

## 现场结论

2026-10-18 只读检查确认：港澳台约十分钟的采集 timer 仍在运行，能自动选中活动 3，但线上独立采集镜像仍使用旧共享认证模块，没有公开版本协商。其发现阶段固定使用 1.0.3，返回 `game_rpc_unknown`，在 SDK 登录前失败。公开榜单仍为活动 2、`stale`，最后观察时间为 2026-10-17 06:49:24 UTC（北京时间 14:49）。

无账号复现：用线上旧镜像执行 `GameClient().discover()`，捕获固定错误码后断言发现成功，得到 `AssertionError: ranking collector cannot discover current server`。同一主机上已经升级的认证服务用三服 `GameClient.discover()` 均成功，按官方提示从 1.0.3 协商到 1.0.6。故障在独立采集程序的交付版本，未发现 timer 或自动活动选择停用。

## 接入方案与实现

保留现有原子发布、无角色停止、认证失败暂停及不可覆盖归档。显式区服贯穿 SDK 语言、官方目标主机、榜单来源、发布和归档目录；三服使用独立状态、共同登录锁，避免同账号任务并发登录。

直接共用港澳台投影无法约束今后的跨服差异；分别新增完整内容生产链超出本次榜单范围。因此使用已验证投影加官方表一致性门禁：登录前比较内容绑定的港澳台版本与目标服当前版本的四张相关表；任意不一致即停止，不猜活动。生产操作和回滚步骤见 `docs/RANKING_OPERATIONS.md`。

目前三服 Master 版本号不同，但官方清单中四张表的哈希与长度全部相同。实服探测使用当前公开活动 3 的 ChallengeMusic ID 7、8、9，对应 LiveMusic ID 100114、100081、100104。没有查询其他玩家的私有资料或修改游戏数据。

## 验证与边界

- 用服务器现有账号与已升级认证镜像分别登录 EN、韩服，已有角色检查、游戏认证和三张单曲榜读取全部成功；每服每张榜返回 100 条、100 个高分队伍字段。检查重复玩家、分数范围及排序，原始响应仅在进程内存中处理，不输出或落盘。此探测证明当前榜单可读，未完成新采集镜像的完整队伍解码、原子发布或浏览器验收。
- 69 项 Python 回归覆盖协商版本传给 SDK 和榜单、三服发布隔离、表差异时认证前停止、受限 CDN/清单、分服最终归档及跨服登录锁；共享认证、维护检测一并验证。前端现有榜单响应、队伍与过期状态的 7 项测试通过，工作区来源边界扫描无发现。
- 从本机直接运行本次修改后的 `RankingClient.discover()`，三服均选中活动 3 并协商到 1.0.6；EN、韩服分别通过四张表的在线一致性门禁，内容来源 Master 版本正确绑定。此验证不使用账号，也不向生产主机上传源码。
- 真实账号只做有限只读探测，不保存凭据、官方令牌或完整玩家数据。使用现有受限文件只读挂载，容器日志关闭。
- 本地改动已准备；自动审批拒绝向现有生产主机上传采集器源码与模板，理由是缺少对这批源码传输的明确授权。未上传源码、构建远程镜像、替换服务或启用新增 timer。线上旧快照尚未更新，须获准上线后再验收三服公开接口与后续定时采集。

未扩大原有榜单类型：当前活动只采集已支持的三张单曲榜；总歌曲榜继续明确标为未采集。
