# 配队搜索性能优化与证明复核（2026-10-16）

本任务从发布分支 `419938267ce78f80b06dbffcf7c70595754b2efc` 创建独立 worktree 与 `codex/team-search-performance`，未修改发布分支，未推送、创建 PR 或部署。交接中的 `3861c0f` 是旧快照；本任务保留起点已有的配色、排行榜、技能展示等整合。

## 目标和取舍

先 profile 和建立相同输入、相同模型的基准，再减少证明开销。首轮测量固定完整卡库，1000 个展开节点，Node v24.19.0：8.39 s。CPU 采样的主要自身耗时是最大综合力匹配约 1.99 s，普通上界约 0.81 s，联合上界 assignment 约 0.65 s，其他包络、配对资料与分组成本分散在相应模块。采样只用来找瓶颈，不作为最终性能收益。

考虑的方向：加强上界可以减少展开数，但需要重新论证并可能加重每个节点；多 Worker 会增加内存和前沿同步成本；优先减少现有安全上界之间的重复工作，保留原评分、合法空间与 Lawler 分区。本轮选第三项。匹配仍是重要剩余成本，未改匹配实现，也未增加并行执行。

## 实现

1. 把当前证明目标的已评分阈值传入联合上界。每个 lambda 和资源价格迭代都独立产生安全上界；一旦足以判定该分区无法改进，就立即结束迭代。
2. 先计算联合上界；足以剪枝时，不再构造逐音符包络、计算旧的逐音符及独立技能 assignment 上界。未能剪枝时仍取原来各安全上界的最小值。
3. 已安全排除的子分区不进入前沿，避免保留其解和边列表。原 Lawler 分区仍覆盖所有其他合法队伍。
4. 每个评分上下文以 WeakMap 缓存配对的固定技能增量与五位置均值；最大技能增量只计算一次。缓存不跨歌曲、目标、账号或任务复用。包络按需生成后复用，原有大小限制不变。
5. 增加完整评分、筛选评分、评分缓存命中、同技能上界内部重放的计数。独立的串行 ABBA 工具记录实际源码、评分 JSON、输入指纹、Node/V8/CPU/系统、墙钟、CPU、峰值 RSS、展开数和证书。

## 最优性论证

设一个分区的合法队伍集合为 D，已完整评分的最佳值为 L。原证明保证每次联合松弛计算出的 U 都满足 `max(score(D)) <= U`。如果 `U <= L`，继续收紧 U 对第一名证明没有帮助，可直接排除 D。提前返回的 U 可能比完整迭代后的界更松，但仍不小于分区最优值。只有这种已经排除的分区会使用提前返回值；其他分区仍完整计算原有上界，以原有优先级展开。

子分区创建时的 L 不会在同一会话中降低，所以立即丢弃 `U <= L` 的分区也安全。完整队伍在跳过 120 顺序评分之前仍先取得自己的安全上界；它所在分区的其他子空间照常划分。没有从卡库删除低稀有度、弱综合力或特定技能的卡。

缓存只记住固定上下文中相同配对的相同增量，不改变浮点计算顺序或向上误差余量。额外的评分计数不参与搜索决策。旧活动收益搜索保留原路径；第一名证明不扩展到两个备选的排名。
