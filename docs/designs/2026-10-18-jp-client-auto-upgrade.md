# 日服客户端自动升级设计

状态：方案已由用户批准；实现前设计。任务分支 `codex/jp-client-auto-upgrade`，基线与交付目标均为 `codex/release-2026-10-18`。不直接合并 main。

## 目标与成功标准

日服每次强制升级客户端时，版本探测应转入完整恢复、下载、签名验证、metadata 解码、旧材料位置重定位与资源样本验证，再执行现有内容生成和发布。不能继续锁死 1.0.5，也不能将失败或未知客户端标记为无变化。

自动化支持已验证加密及认证材料不变、位置移动的升级。密钥/认证材料轮换、metadata 格式改变、不支持的 Unity 或分包结构、下载源尚未同步应明确阻断，保持旧公开内容。自动升级不意味着支持任意未来加密算法。

## 方案选择

采用完整自动升级。只支持人工提供新包虽然改动少，但不能消除每次维护后的人工介入；仅去掉版本或摘要校验会破坏可信输入边界，不采用。

## 信任和数据流

1. 保留当前 1.0.5 的签名、metadata 摘要和解密/NetworkConfig 位置作为迁移信任锚，不将它继续当作唯一可运行版本。
2. JP 专属升级信号携带经过格式校验的推荐版本。gRPC 非成功响应及成功响应中的推荐版本变化均转为该信号；Global 的 APK URL 规则不能误用于日服商店链接。403、维护、认证失败保持实际失败，禁止伪装升级或无变化。
3. 快速探测遇到升级返回 `needs_full`，只恢复一次完整私有状态；完整探测执行升级。没有升级需求时不下载大包。
4. 包获取沿用现有 APKPure 传输来源，自动读取最新 XAPK；下载只允许 HTTPS 和明确允许的 CDN 主机、限定重定向、大小及超时。镜像不是信任来源：推荐版本必须来自官方 Version RPC，新包版本必须精确匹配、versionCode 递增、包名不变，所有分包均通过 Android APK 签名验证且证书与可信锚一致。镜像仍为旧版时等待下次运行，禁止发布旧数据冒充新版本。
5. 在独立临时目录解码 metadata，检查结构与 Unity 身份。从固定摘要的旧 metadata 取材料，仅在内存比较；在新 metadata 唯一定位解密 FieldRefs 和认证字符串索引。至少三个不同的包内加密资源必须解出 UnityFS 头。再以新客户端调用官方 Version RPC，验证新身份可用后才接受 seed。
6. 私有 seed 回执绑定客户端版本、versionCode、所有 APK 摘要、metadata 摘要、Unity、解密和认证位置；不保存明文密钥/密码。保留摘要锚定的旧 metadata 供后续升级复核。临时目录完整验证后替换 seed，任一步失败恢复旧 seed，保留 workspace。
7. 生产入口、资源读取、输入指纹、轻量回执和 checkpoint 都读取同一个经验证的客户端身份；轻量恢复包含小型绑定回执与可信 metadata。旧回执可转完整路径建立新回执，不能跳过变更。
8. 原有功能检查、上传读回、checkpoint 和公开指针 CAS 继续执行。升级成功只代表输入可用，不能提前报告网站已更新。

## 模块边界

- `jp_client_profile`：旧信任锚、metadata/绑定回执验证、位置重定位；接口返回版本和位置，材料仅在调用过程中留在内存。
- `jp_client_refresh`：下载和分包/签名验证、临时 seed、资源验证、官方探测、可回滚替换。
- `jp_public` / `jp_remote_sync`：地区专属升级信号、按绑定生成只读官方客户端。
- `jp_phone_inputs`：使用绑定解密，校验观察版本与 APK 身份。
- `r2_production_gate`：轻量升级转完整恢复、完整输入身份和新回执；无变化门禁不接受部分升级。
- 工作流：将日服升级接入完整探测的既有受审运行时及日本出口，去掉固定版本下载步骤。原生调度延迟是独立问题，不在此任务中改变生产调度。

## 验证和发布边界

本地先验证失败不换 seed/指针、错签名/版本/歧义材料拒绝、成功升级后恢复和下次无变化；同时回归 Global。真实包验证需要新包实际可获取，结果单独记录，不用模拟测试代替。

生产工作流当前只允许默认分支执行；今日集成分支合并不自动等于云端可验证。先在分支完成本地验证，再由正式发布流程交付已审核的代码。是否重建更新器镜像由依赖差异决定：生产脚本通过 checkout bind mount 运行，纯 Python 源码变化本身不要求重建镜像；若新增运行时依赖则先构建并固定新镜像。

云端先运行 shadow，验证恢复、新客户端接入、全量内容、功能门禁、上传读回和私有 checkpoint，公开 current 保持不变；成功后再正式 promote，并核对两服页面交叉引用。shadow 会写私有 checkpoint 和不可变内容，需要单独发布授权。当前授权是开发、验证和合入今日集成分支，不包含 main 合并、生产配置变更或正式晋级。
