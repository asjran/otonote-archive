# 活动收益配队的性能与正确性

## 目标与范围

固定正式规则、合法 owned 卡库及实际养成、账号、谱面、活动、模式、收益目标、分数 basis、火力/CP 预算和续打候选。第一名对所选目标必须有模型内最优性证明；最多两个备选只供参考。默认目标是收益元组，`grade` 先比较档位，再比较道具和活动 pt；`refineScoreTies=true` 另外要求同收益下最高期望分。普通与挑战分开计算。续打最优性以明确提供的 challenge rows 为边界。

不能用减卡、缩减技能顺序、忽略次级收益、降低评分精度或更改收益模型换时间。全部结果沿用正式评分器，收益计算保留整数取整及有限 CP 的整数场次。

## 测量方案与待验证假设

`tools/benchmark_event_yield_search.mjs` 在独立冷进程内调用生产入口，默认使用全部成员/留影和合法最大养成，最大账号按升级表得到，scope 固定为 owned。可传本地 inventory/draft 覆盖默认值。续打 rows 必须由固定文件输入，避免把另一项优化任务的输出混入输入变化。

先测冻结基线，记录阶段耗时、展开数、完整评分总数、frontier、进程 RSS 峰值、收益元组及最优性证书。完整评分总数是 practical + exact + bound；缺少任何计数时标 incomplete，不将缺失解释成零。源码、输入文件及完整输入、环境和评分模型各有指纹。

按测量结果依次验证以下假设：

1. 以第三名作为停止门槛会在第一名已最优后继续搜索。仅将证明门槛改为第一名，保留全部合法分区与三个已计算结果。
2. 默认忽略期望分 tie 的收益搜索，仍计算另一条期望分上界，浪费评分和界计算；显式要求 refine 时才需要。
3. 同档位/奖励加成或相同 CP 的奖励界、续打计划重复求值，可在单次任务内按完整依赖缓存。
4. 评分界过松时需测量联合上界；只有在安全上界证明和同输入测量支持时才启用，不把更小的非法候选范围作为剪枝。

串行 AB/BA 对照使用同一 Node、规则、输入、时间/展开预算、机器和基准脚本。完整证明与限时样本分开报告；只有两边均完成证明，才报告完成同一证明任务的提速倍数。评分模型指纹不同的运行不作为搜索性能对照。

## 最终搜索的覆盖与剪枝依据

先用全部合法成员／留影分别求道具与活动 pt 的最大加成。这个向量可以不可同时实现，它只作为保守上界。尝试一支“总加成优先、真实综合力打破平局”的合法匹配，完整复算 120 个技能顺序。只有其完整收益元组达到逐档扫描得到的全局上界时才能提前证明。此时可以只返回第一名，`topNComplete=false`，不会为两个未证明名次额外评分；当前队 delta 没有另行计算时为 null。

未达到上界时保留原 practical 候选，再逐队长、逐档位检查是否仍有严格更好的方案。对固定档位，用正式 rewards 函数和实际所选主目标的续打规划，二分求满足目标所需的最小整数加成。严格改进域分为“主收益严格提高”和“主收益不降、次级收益严格提高”。grade 目标先比较档位；全部档位分别处理，不假设档位奖励单调。`refineScoreTies=true` 沿用完整的期望分 tie 搜索。

加成和的 DP 保留五个不同角色、五张不同留影和已指定卡片，放宽配对与禁边限制。将奖励二分所得阈值向上取到这个超集中的下一个可达加成和，仍不会遗漏合法队伍。DP 超过 20,000 个状态时回退未收紧的阈值。

对于必要约束 `primaryBP >= T1, secondaryBP >= T2`，任意非负整数 a/b 都给出必要条件 `a*primaryBP+b*secondaryBP >= a*T1+b*T2`。联合上界保留同一配对的综合力与技能；每一个参数产生独立安全上界，迭代只影响紧度。对该条件域，若“包含某成员／留影 + 其余卡分别取独立最大加成”仍达不到阈值，才从这个条件域的松弛中删除其边。这不从真实搜索卡库删卡。

完整搜索先对成员／留影集合做 include/exclude 二分，两个子域互斥且覆盖父域。指定某成员后，同角色其他变体不能并存；五张成员或留影指定完毕后，其他同类卡才能排除。中间节点的界允许放宽已指定卡片，所以只会更松。固定十张卡后，继续用 Lawler 对配对分区。被分区移除的代表队必须完整评分，或者先用该完整队伍的安全上界证明不能严格改进；所有子分区继续处理。只有全部队长的全部待处理域都排除后才证明第一名。若见证提高了 incumbent，只需重查当前档位，先前排除的域对更强 incumbent 仍成立。

联合上界的 `matchingCalls` 仅统计该辅助上界内部匹配次数，不是全搜索的所有匹配调用。正式评分次数另计 practical、exact 及 bound 内部调用，包含失败见证和证明中的代表评分。

## 缓存与 API 边界

候选／综合力缓存先校核规则内容摘要，包含活动 power 效果，不能只凭相同 release metadata 复用旧配对权重。仅 LiveMusicScore 评分表变化可以复用合法候选准备，原始分数缓存另行失效。见证缓存只提供候选卡片，证明用的全池加成上限每次重算。

正式规则对象在一次任务中应不可变；修正规则应传入新对象。评分／养成库还有按对象身份缓存的索引，本次没有承诺支持任意规则表的原地修改。回归覆盖新规则对象、相同 metadata 下 EventEffect power/reward 修正，以及 LiveMusicScore 修正的冷暖结果一致。

后续挑战最优性仍限定为提供的 rows。单谱面的第一名证明不等于整个 Worker 的歌曲比较已完成，完整歌曲遍历也不自动代表每个目标均已证明。批量工具分别记录 `complete` 和 `allProven`。

## 批量执行与证书展示

生产 Worker 与 `benchmark_event_yield_batch.mjs` 共用 `runEventYieldBatch`。完整模式显式传入 `maxEvaluations=0`，启用完整收益证明；快速模式保留 24 次有限搜索预算，不执行昂贵的完整联合界证明。默认不要求期望分 tie 的完整模式先尝试合法见证，并保留全部候选的逻辑覆盖；若上界不可达到、跨曲证明不支持、发生异常或未完成，则回退原候选域的逐曲完整搜索。显式 refine 与非 AP 情景保留原完整目标的逐曲路径。

跨曲剪枝同时比较主收益、次收益与歌曲时长；同收益但更短的歌曲仍可能改进第一名。both 两个目标分别证明，不用一个目标的领先结果代替另一个目标。完整循环先计算所选挑战候选，再将其结果作为普通阶段续打范围；两个阶段保留独立卡库 scope 与分数 basis。

六张代表曲上的 practical 搜索只负责提供合法起点。进一步从本次各目标领先队伍中各取至多两支，把它们的同一组合法十卡配对迁移到所有所选谱面，用当前谱面的正式评分、实际养成及本目标的收益／续打 transform 重新评分。该步骤不硬编码实测找到的队伍或谱面 ID，不把一个目标的奖励直接复用到另一个目标；它只改善 incumbent，全部谱面和卡库仍由后续证明覆盖。跨谱面新增评分记入 `transferScores` 和完整评分总数，缓存命中另计。

`coverageComplete` 表示所选域已由完整搜索或全局证明覆盖；`fullyOptimizedCharts` 只统计各目标单曲第一名均已证明的谱面，`prunedCharts` 单列被全局上界覆盖的谱面，`allProven` 保留严格的逐曲证明含义。全局证明不承诺未求解歌曲的单曲最优配队。UI 仅在覆盖完成且各目标证书齐全时展示“所选条件的收益第一名已证明”，并注明备选与期望分 tie 的边界。

批量工具预检完整候选集中的所有谱面及来源，不因缺本地文件缩小范围。默认 EXPERT 的 88 张普通谱面和本期 3 张挑战是当前正式筛选；全部难度为 352 张普通和 12 张挑战，两个规模分开报告。eco 开关保留生产 scheduler 的语义，关闭 eco 的 CPU/墙钟结果不能冒充默认 eco 的耗时。

这些是本地冷进程的计算基准：输入 JSON 已在计时前预检并加载，计时包含相同生产 runner、阶段、目标、评分及调度，未把公开谱面网络下载或 IndexedDB 读写算进 CPU／墙钟。生产 Worker 共享算法与证书路径，但实际浏览器首次加载还有网络和持久化成本。本机样本不是任意卡库／谱面／浏览器的统一耗时保证；完整模式坚持证明，未完成或取消时如实标未证。

## 重建数据与重跑

`2026-10-18-event-yield-chart-manifest.json` 持久保存全部 352 张谱面的不可变公开 URL、大小与 SHA256，以及 catalog 的 release 和 SHA256；另含重新从该发布公开 URL 取回的原始正式规则与乐器投影 SHA。原始规则与投影重新合成后的对象，已校核与实际基准规则完全相等。原始公开规则与乐器投影的不可变 URL 已记录；本地快照包用于本次离线复现，长期保存需交接接收方另行归档，不能依赖 `/tmp` 永久保留。源码发布检查禁止二进制运行输入，因此实际 enriched 规则（85,996 bytes）和 catalog（212,246 bytes）的确定性 gzip 快照保存在仓库外 `/private/tmp/otonote-team-search-reproduction-20261018/`，作为本地交接复现包；压缩／解压 SHA256 见 `2026-10-18-event-yield-rule-snapshot.json`。本地规则快照已有同源 750 条 BandItemLevel，不需要另行修改等级表。重建命令为：

```sh
gzip -dc /private/tmp/otonote-team-search-reproduction-20261018/event-yield-global-500-rules.json.gz > /absolute/path/data.json
gzip -dc /private/tmp/otonote-team-search-reproduction-20261018/event-yield-global-500-catalog.json.gz > /absolute/path/catalog.json
python3 tools/fetch_event_yield_benchmark_charts.py \
  --manifest docs/designs/2026-10-18-event-yield-chart-manifest.json \
  --catalog /absolute/path/catalog.json --output-dir /absolute/path/chart-cache
node tools/benchmark_event_yield_batch.mjs \
  --data /absolute/path/data.json --catalog /absolute/path/catalog.json \
  --chart-map /absolute/path/chart-cache/chart-map.json \
  --event 2 --include-challenge --no-eco --time-limit-ms 300000 \
  --evaluations 0 --cpu-limit-ms 0 --output /absolute/path/result.json
```

下载器最多并发四个公开请求，校核 catalog 来源、每张文件大小／hash／ID后生成 `{"music-chart-10000103":"/absolute/path/music-chart-10000103.json",...}` 形式的 chart-map。本次已下载数据完成全部 352 项校核；重建下载工具本身只做静态语法检查，未再次下载同一批文件。macOS 正式计时在 node 前加 `/usr/bin/caffeinate -i`；其他平台需记录环境，不能套用本机数字。默认是完整 EXPERT 筛选，全部难度另加 `--difficulty all --challenge-difficulty all`。默认 eco 不加 `--no-eco`，其耗时单独报告。full batch 工具拒绝非零 evaluations，避免与生产 full 固定无限预算的语义不符。

如果输入来自尚未包含 BandItemLevel 的同发布原始规则，可传 `--data formal-scoring-rules.json --band-items band-items.json`；生产升级行投影器核对两者的 sourceReleaseId 后合成，不借另一发布的升级表补齐。已含完整表的基准快照不需要这个参数。

最终额外校核：两个 gzip 解压 SHA 与实际规则／catalog 输入完全一致；原始公开规则＋同源乐器投影通过 batch preflight，91 个阶段谱面／182 个目标调用、缺失 0。runner／UI 的 18 项测试通过，包含取消、失败、fallback、独立阶段约束及全域证书文案。全量 Node、独立联合上界／跨谱面 oracle 与构建结果由主任务验证报告统一记录。
