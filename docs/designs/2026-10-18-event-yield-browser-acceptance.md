运行期间实际展开计算条件，约 41.7 ms 更新显示；默认节能的跨谱面证明阶段切换「pt 优先方案」，约 65.5 ms 更新显示，选中状态正确。没有记录到运行及最终证明显示期间大于 50 ms 的主线程 Long Task；两轮窗口错误均为空，最终浏览器 console 为 0 errors／0 warnings。没有提前展示第一名证明；最终证明文案在完整结果收到后 29.2 ms 才出现。

原始定时器最大延迟分别为 72.4／717.8 ms，不能仅用 P95 宣称没有尾部暂停。717.8 ms 事件结束于 epoch `1792314324640.6`，实际执行的 Playwright 可访问性快照输出完成于 `1792314324651.3`，两者吻合。停止所有计算 Worker 后，执行相同 `playwright-cli snapshot` 在空闲页复现 **696.7 ms** 延迟，也没有 Long Task；原始运行其余计时器延迟最大 78.3 ms。机器证据保留未修剪的 717.8 ms，以及独立的空闲快照复现，不将工具抓取快照的暂停归为搜索吞吐或产品交互保证。

## 取消、重启与证明显示

修复后实际测试三个时点：

| 取消时点 | 发起操作至 terminate | 结果 |
|---|---:|---|
| Worker 初始化、尚无部分结果 | 24.9 ms | 运行按钮恢复，取消按钮隐藏，无旧消息 |
| 已产生部分方案 | 138.5 ms | 保留显示方案，允许重新开始，旧任务消息数保持 28 |
| 跨谱面上界证明正在执行 | 38.6 ms | 终止成功，busy=false，旧证书未沿用，后续消息数保持 2,139 |

在取消后通过页面按钮重新开始，创建新 Worker 并完成了默认节能全域证明。改变省电设置时旧证书和结果立即清空；旧 Worker 的消息及 error 不会覆盖新状态。三个取消样本均没有被标成完成或第一名已证明。

实际发现并修复：

1. 原取消文案暗示继续复用当前进度，但 terminate 后会丢失 frontier 和未落盘状态。按钮改为「重新开始完整比较」，明确从头搜索，只承诺复用已保存的估分缓存。
2. 部分进度向用户显示 `practical-result` 等内部阶段名。增加中文阶段映射及未知阶段回退，相关 detail 同步替换；最终浏览器观测未再泄漏这些阶段名。
3. 「完整求解 12 张」收紧为「已证明 12 张谱面的单曲第一名」，与全局覆盖、参考备选和默认期望分 tie 的边界保持一致。

后续挑战的最优性仍限定本次已计算 challenge rows，不是任意 CP 消费下任意挑战配队的更大联合搜索域。备选仅供参考，默认同收益期望分排序未证明。取消不是从 frontier 续跑。
