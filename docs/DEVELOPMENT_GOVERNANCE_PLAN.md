# 开发与发布规范化实施计划

状态：实施中。日期：2026-10-02。

## 已确认的目标与约束

- 保留单仓库，分开代码交付、内容生产和运行维护；复用现有不可变产物、锁、原子切换和回滚机制。
- 共享计分核心只调整代码归属。公共派生结果在内容生产端计算，个人配队和交互计算继续在浏览器及 Web Worker 运行。
- 线上当前生效配置是迁移行为基线。实际配置、凭据、私有输入、原始运行报告不进入 Git；仓库只保存模板、契约、校验程序及脱敏说明。
- 保留现有工作区成果。先记录本地和线上基线，不重置工作区，不将整个现有 Git 历史或未审查文件上传。
- 生产变更必须有具体候选、校验结果、旧版本保护和回滚步骤。磁盘回收只作用于已识别、无有效引用且超过保留期的产物。

## 方案选择

采用现有单仓库内的模块隔离与统一交付。暂不拆多个仓库或引入微服务集群；这两种方案会增加契约发布和运行成本，也不能直接解决当前版本追溯与配置漂移。

## 阶段与验收

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| 0 基线 | 私有本地工作区摘要、线上版本与运行状态摘要 | 保留已有成果；报告不包含秘密或真实配置值 |
| 1 配置与脱敏 | 提交/发布文件检查、配置排除、脱敏模板、源码导出边界 | 真实部署配置和凭据被拒绝；错误输出不泄漏值；干净导出可重复 |
| 2 共享计算 | 独立计算模块与网站兼容入口 | 两端使用同一实现；不新增计算 API；关键计分回放结果保持一致 |
| 3 代码交付 | 独立代码构建、版本来源清单、CI、统一发布验证 | 指定提交可构建；文件摘要和测试证据绑定；预览与发布使用同一产物 |
| 4 程序与配置 | 不可变程序包/镜像交付及外置配置契约 | 源码、配置、数据各自可追溯；沿用线上行为；配置不随程序打包 |
| 5 运行维护 | 独立存储审计/保留工具、任务状态与故障处置 | 空间不足时仍可安全审计；保护两服及预渲染引用；失败不伪装成功 |
| 6 集成验收 | 定向与全量测试、干净导出构建、发布演练、脱敏交付报告 | 本地与线上验证分开记录；真实阻塞明确记录；无未经检查的推送 |

## 模块职责

1. 采集与解析：获取和验证输入，输出内容候选，不操作网站当前版本。
2. 共享计算：显式接收数据与规则，输出计算结果，不读取部署配置，不依赖页面或 DOM。
3. 网站：构建页面及浏览器运行库，通过版本化内容契约消费数据。
4. 交付：验证产物与来源，安装、切换和回滚。发布命令不重新构建被验收的产物。
5. 运维：监测最后成功时间、失败原因及磁盘；配置值仅存在受保护的运行环境。

## 验证策略

- 离线单元/契约测试使用小型合成样例；真实资源回放与公网验收独立执行。
- 共享计算优先运行现有计分、排行与 Worker 测试，验证依赖方向和浏览器打包。
- 发布与脱敏涉及实际保护边界，覆盖损坏产物、提交不一致、缺失证据、配置混入、敏感错误输出等失败路径。
- 最后执行一次完整可用测试套件，记录既有失败与本轮回归；不得以跳过检查充当验收通过。
- 不上传真实配置、凭据或完整私有历史。仓库目标不明确时继续完成本地可审查交付，并核实目标后再发布。
